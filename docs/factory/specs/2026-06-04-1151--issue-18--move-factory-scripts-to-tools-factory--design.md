# Move `tools/scripts/factory` → `tools/factory`

## Problem

The factory orchestrator scripts live at `tools/scripts/factory/`, three levels
deep. That nesting is heavier than the directory warrants and makes the tree
harder to navigate. Flattening to `tools/factory/` keeps the related automation
(`tools/scripts/seed.ts`, `tools/eslint-rules/`) as siblings while shortening the
path.

This is a pure relocation refactor: no behavior changes, no new code.

## Architecture & approach

Move the whole directory with `git mv`, then update the references that point at
the old path — both the external callers (Reference updates) and the path
couplings _inside_ the moved test files (Test path couplings).

- `git mv tools/scripts/factory tools/factory` relocates all 10 source `.ts`
  files, the `__tests__/` subfolder (7 test files), and `.gitkeep` in one
  history-preserving operation.
- The sibling-to-sibling imports between source files are **relative** (`./github`,
  `./claude`, `./plan`, `./plan-gen`, `./task-run`, `./pr-finalize`,
  `./spec-author`), so they resolve identically at the new location — no edits.
- **However, the move shortens the path by one level** (`tools/scripts/factory/`
  → `tools/factory/`), which breaks two kinds of path-coupled code in the test
  files. These are NOT zero-edit and are enumerated under "Test path couplings"
  below.
- `.gitkeep` is now redundant (the directory holds real files) but is left in
  place to keep the move atomic and the diff minimal.

Rejected alternatives:

- Moving files individually — loses the atomicity of a single `git mv` and risks
  missing a file; no upside.
- Also flattening `tools/scripts/seed.ts` and `tools/scripts/lint-fix.sh` up a
  level — out of scope (YAGNI); the issue is specifically about the `factory`
  subtree.

## Reference updates

Six external string references point at the old path, `tools/scripts/factory`
→ `tools/factory`:

| File                                         | Occurrences                    |
| -------------------------------------------- | ------------------------------ |
| `.github/workflows/factory-go.yml`           | 1 (`bun …/workflow-go.ts`)     |
| `.github/workflows/factory-revise.yml`       | 1 (`bun …/workflow-revise.ts`) |
| `.claude/skills/factory-issue/SKILL.md`      | 3 (description + 2 commands)   |
| `.claude/skills/factory-brainstorm/SKILL.md` | 3                              |
| `.claude/skills/docs-factory/SKILL.md`       | 1                              |

### Test path couplings (inside the moved files)

Three assertions inside the moved test files hard-code the old depth/path and
must be updated, or `bun test` (a verification step below) fails. Note these use
the segment `scripts/factory` **without** a `tools/` prefix:

- `tools/factory/__tests__/spec-author.test.ts` line 10 — the cross-directory
  import reaches the repo root with four `../`:
  `"../../../../.claude/hooks/factory-spec-frontmatter"`. After the move the
  directory is one level shallower, so this overshoots the repo root and must
  drop one segment → `"../../../.claude/hooks/factory-spec-frontmatter"`.
- `tools/factory/__tests__/issue-create.test.ts` line 53 — the spawned CLI path
  `"scripts/factory/issue-create.ts"` → `"tools/factory/issue-create.ts"`.
- `tools/factory/__tests__/issue-create.test.ts` line 66 — the cwd-deriving regex
  `/\/scripts\/factory\/__tests__$/` no longer matches the new directory and must
  become `/\/tools\/factory\/__tests__$/` (so cwd still resolves to the repo
  root).

These three lines are the reason the move is not zero-edit. Every other `.ts`
file is moved as-is.

Explicitly **not** edited by hand:

- `docs/factory/factory-process-guide.md` — regenerated by the `docs-factory`
  skill as the final step, so it reflects the new path from a fresh read of the
  pipeline rather than a manual find/replace.

Untouched — no reference to the path at all:

- `tsconfig.json` (matches `**/*.ts` via a glob), `eslint.config.mjs` (matches
  `**/*.test.{ts,tsx}` and the `__tests__/` location rule), `package.json` (no
  factory script reference), `.claude/settings.json` and hooks.
- The 5 `.claude/agents/*.md` — none reference the script path.

Untouched — contains the old path but intentionally left as a historical record:

- `docs/factory/plans/*.md` — historical plan artifacts.
- `docs/factory/specs/*.md` — historical design specs (including this one, which
  necessarily quotes the old path in its Problem/Architecture text).

## Testing & verification

No new tests — this is a pure move. Verify with:

- `bun test tools/factory/__tests__/` — all 7 suites pass from the new location.
  `spec-author.test.ts` and `issue-create.test.ts` are the path-coupled suites
  (see "Test path couplings") and are the ones most likely to regress, so confirm
  they pass specifically.
- `npm run lint` — clean, confirming the `__tests__/` eslint location rule still
  matches under the new path.
- `grep -rn "scripts/factory" . --exclude-dir=node_modules --exclude-dir=docs`
  returns **nothing**. Excluding `docs/` skips the historical artifacts
  (`docs/factory/plans/*.md`, `docs/factory/specs/*.md` — including this spec)
  that intentionally still quote the old path; every remaining (live) reference
  must be gone. The broader `scripts/factory` pattern (not just the
  `tools/`-prefixed form) is required because the test couplings use the segment
  without the `tools/` prefix; grepping the prefixed form alone would give a false
  "clean" result.
